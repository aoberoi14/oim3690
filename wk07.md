## What I learned

- The two-call pattern for chaining API calls: fetch geocoding data first to get coordinates, then use those coordinates in a second fetch to get weather. Nothing in the second call works without the first one finishing.
- Why `try`/`catch` belongs around a `fetch` specifically: the API is on someone else's server and can fail in ways that have nothing to do with my own code, so the failure needs to be handled separately from my own logic bugs.
- The difference between JSON and a plain JS object. JSON always has quoted keys, which trips me up if I forget when reading a raw API response in the browser.
- Reading raw JSON in the browser before writing any code catches wrong assumptions early, including assumptions AI makes about fields that don't actually exist in the response.
