OIM3690 · Weeks 1–10

Learning to hand AI a finished draft instead of a blank page

Ten weeks of logs, read together. The pattern that shows up over and over: the weeks that went well were the ones where I built something plain and working first, then gave AI a specific job on top of it, instead of asking it to start from nothing. The weeks I learned the most were the ones where something broke live, on the deployed site, and I had to actually go find out why.

The shift

Week 1 versus week 10, same student

Week 1

Described myself in one sentence and asked AI for a complete personal site. Kept nearly the whole thing as-is, placeholder email included. AI was the entire process, start to finish.

→

Week 10

Caught AI's first fix for a broken deploy (keep the API key gitignored) and pushed back, because I understood why that standard advice didn't apply to a static site with no backend. The real fix was mine to reason out, not AI's to hand me.

Week by week

What got built, and where AI actually fit in

01

First week

The whole site came from one prompt

Built a personal portfolio site, first GitHub repo, first commit, first deploy. Learned the GitHub Desktop commit-and-push workflow and that saving a file locally isn't the same as committing it.

AI: described myself in one sentence, AI wrote the whole page, layout, styling, Google Fonts included. Kept almost all of it.
02

05/27 – 05/31

Typed HTML by hand, then broke it on purpose

Wrote hello.html with no copy-paste. Spent longer than expected on a simple image path bug (a file open in VS Code from Downloads isn't the same as a file actually inside the project folder). Deliberately removed a closing tag to see what would happen, and learned that browsers silently absorb broken HTML instead of erroring, which makes bugs harder to catch, not easier.

AI: the assignment called for typing by hand, so AI stayed a reference only, not a finished answer, this is the first week that pattern shows up.
03

06/01 – 06/03

A real client brief, not a class exercise

Wrote a proposal for MP1 using my family's actual agency, Oberoi IBC, as the client. Had AI interview me one question at a time to turn that proposal into a PRD, homepage priorities, contact form fields, the five-agencies section. Built the site with CSS custom properties so one variable change updates every page.

AI: answered the PRD interview honestly based on what I actually know about the agency, then used my own answers, not AI's guesses, as the build reference.
04

06/08 – 06/14

Finished MP1, then went back to first principles

Deployed the Oberoi IBC site. Then, separately, wrote a stylesheet by hand covering element, ID, class, and hover selectors, and built a contact form learning what action, for/id label pairing, and required actually do.

AI: asked AI for a first pass on the contact form and stylesheet, then read every rule and input type before keeping it, rather than shipping it unread.
05

06/15 – 06/21

JavaScript starts, and so does MP2

First real pass at variables, functions, DOM manipulation, and events. Three things that didn't click right away: when arrow functions and regular functions actually behave differently, why addEventListener is preferred over inline onclick, and why logging an object straight to the page just prints [object Object] without JSON.stringify. Picked a run tracker for MP2, since it's something I actually wanted for myself.

AI: used the PRD-interview pattern again for MP2's proposal, same process as week 3, now a repeatable habit rather than a one-off.
06

06/22 – 06/28

Built the whole run tracker, and found three real bugs

Wrote the discount function and half the unit converter by hand before asking AI to extend either one. Built MP2 fully: logging runs, a goal with an animated SVG progress ring, weekly/monthly totals, and a streak counter, all state living in a plain array and object with no external library. Found and fixed three of my own bugs: pace showing NaN on an empty submit, the streak counting a run-free current week, and history not refreshing after a delete.

AI: used AI specifically to sanity-check my streak week-boundary math after hitting repeated off-by-one errors, a targeted debugging question, not a build-it-for-me request.
07

06/29 – 07/05

First real APIs, and a habit worth keeping

Built a render-from-data list, a Dog CEO API fetch wrapped in try/catch, and a POST request to the class message API. Picked Open-Meteo for MP3, a trip weather comparison tool. Learned the two-call chaining pattern (geocode first, then use those coordinates to fetch weather) and started actually reading raw JSON responses in the browser before writing code against them.

AI: caught AI assuming API fields that didn't actually exist, by checking the real response first, and rewrote the MP3 proposal's "why I chose this" section since AI's first draft read more generic than my actual reason.
08

07/06 – 07/12

Finished MP3, and the security lesson that stuck

Deployed the trip weather planner. Learned that .gitignore only protects a key if it's added before the file is ever committed, adding it after the fact doesn't undo history. Learned a second, separate problem: a key loaded into a browser script is readable in DevTools regardless of git history, so real secrecy needs a server between the browser and the API, something GitHub Pages can't provide on its own.

AI: caught a live bug where AI's CSS set display: flex directly on two elements meant to stay hidden until needed, which silently overrode the hidden attribute and froze the page behind a fullscreen panel. Found it by using the deployed site, not by reading the stylesheet, then asked AI to explain the cascade issue and applied a one-line fix, in trip-weather-planner commit fc20a79.
09

Final project kickoff

Reel Log gets proposed, then gets peer-reviewed

Picked a personal movie tracker for the final project, built on the TMDB API, and wrote the proposal with an honest "what I don't know yet" section. Got real peer feedback: a classmate flagged the planned recommendation feature as more scope than I needed, and pointed out I had no way to browse a growing log. Cut the first, added sort/filter instead, before writing a line of code for either.

AI: used AI to brainstorm project directions, but made the actual scoping call, both the original pick and the post-feedback cut, myself.
10

Building and deploying

The same security lesson, revisited with more nuance

Built Reel Log fully and deployed it. Search stopped working after deploy, and the fix wasn't what week 8 would have predicted: this time the API key needed to be committed, not gitignored, because a static site with no backend has nowhere else for the browser to read it from. Separately, found genre and decade bar charts rendering with zero height, traced it to <span> elements ignoring CSS height by default, and fixed it with one display: block rule.

AI: pushed back when AI's first instinct repeated the week-8 pattern (hide the key) in a situation where that pattern actively broke the app, the same lesson, applied with more judgment the second time.

What actually changed

Reading all ten side by side

Build the plain version first, then give AI one specific job. This starts in week 2 (typing HTML by hand because the assignment asked for it) and becomes a deliberate habit by week 6 onward, write the discount function or the streak logic myself, then hand AI a narrower extension I can actually check against something I already understand.

The real debugging happens on the deployed site, not in the editor. Three of the sharpest lessons in these logs, the week 6 streak bugs, the week 8 [hidden] override, and the week 10 bar chart, weren't caught by reading code. They were caught by using the live app and noticing something looked wrong, then working backward.

The same lesson can need a second pass. Week 8 taught that a key needs a server to stay genuinely secret. Week 10 required learning the more specific, less intuitive corollary: on a static site with no server option at all, the "safe" answer from week 8 actively breaks the app, and the key has to be committed instead. Same topic, sharper judgment the second time around, not a contradiction.
