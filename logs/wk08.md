## What I learned

Committing .gitignore before the key file exists is what actually keeps a secret out of git history, not just adding the filename to .gitignore after the fact. If the file was ever tracked first, ignoring it later doesn't undo that, the key is already sitting in a past commit.

Keeping a key out of the repo isn't the same as keeping it safe on a live site. My ai-chat page loads config.js with a script tag, so if I ever pushed that file, anyone could open DevTools on the deployed page and read the key straight out of the Network tab or the page source, regardless of what git history shows. That's why the exercise has the chat feature only work locally, the deployed version of ai-chat is intentionally missing config.js and won't actually call the API. A key that has to stay secret for real, not just for a class exercise, needs a server sitting between the browser and the API so the browser never sees it at all, which GitHub Pages can't do on its own since it only serves static files.

Reading a hidden HTML attribute and CSS display rules together taught me something about the cascade I hadn't run into before. Setting display directly on an element in your own stylesheet beats the browser's built-in hidden styling even when the hidden attribute is present in the markup, because author CSS takes priority over the user agent's default styles at equal specificity. I only found this by watching the actual bug happen on the deployed site, not by reading the CSS and spotting it ahead of time.

## AI interactions

The one I want to document closely: AI's first pass at style.css for MP3 set display: flex directly on .detail-panel and .search-results, the two elements on the page that use the HTML hidden attribute to stay invisible until needed. That rule silently overrode hidden, so both elements rendered on page load, and the fullscreen detail panel sat on top of the whole page blocking every click except its own close button. I didn't catch this by reading the code, I caught it by opening the live site and seeing an empty box under the search bar and a dimmed page that felt frozen. I asked AI to explain why something marked hidden was showing up, and it walked me through the cascade issue and gave me one fix, a global [hidden] { display: none !important; } rule added near the top of the file. That change is in the trip-weather-planner repo, commit `fc20a79`.

Smaller one worth mentioning: I asked AI to build out ai-chat/script.js after I already had a working hand-written askAI() call. I kept the fetch call and the way it reads the reply, since it matched an actual OpenAI response I looked at, but the first version of the chat log it wrote replaced the entire conversation on every new message instead of appending to it, so I had it fix that specifically rather than accepting the whole file as is.
