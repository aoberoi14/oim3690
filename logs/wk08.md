## What I learned

- `export`/`import` between modules only works when the script tag that loads the entry file has `type="module"`, and only that one file needs to be linked in the HTML, everything else it imports comes along automatically.
- Why the OpenAI Responses API key has to stay out of GitHub entirely, not just out of the visible HTML: committing `.gitignore` first, before ever creating the file with the real key, is what actually prevents it from landing in git history.
- The HTML `hidden` attribute has a default browser style, and any CSS rule targeting the same element with an explicit `display` value will override that default. This came up directly on MP3 (see AI interaction below).
- Running `git status` before a commit is the actual way to confirm a file like `config.js` isn't about to get pushed, not just trusting that `.gitignore` is doing its job.

## AI interactions

**AI output I did not accept as-is:** When AI first built `style.css` for the MP3 detail popup and search results dropdown, both elements had the HTML `hidden` attribute in the markup, but the generated CSS set `display: flex` directly on their classes (`.detail-panel`, `.search-results`) with no rule accounting for `hidden`. This meant both elements showed up on page load instead of staying hidden, and the fullscreen detail popup blocked every click on the page except its own close button.

I caught this by actually opening the deployed site and seeing an empty box and a dimmed fullscreen overlay that made the page feel frozen, not by reading the CSS and spotting it in advance. I asked AI to explain why a `hidden` element was rendering, and it identified the cascade issue: an author stylesheet rule with `display: flex` beats the browser's default `hidden` styling even though `hidden` is present in the HTML. The fix was one added rule, `[hidden] { display: none !important; }`, placed near the top of `style.css` so it applies globally regardless of what other classes are set on a hidden element. That change landed in the `trip-weather-planner` repo in the commit where I updated `style.css` after the site was already deployed and broken (see commit history on that repo for the exact hash, made the week of 7/6).
