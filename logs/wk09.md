Kicked off the final project. Brainstormed a few directions before landing on Reel Log, a personal movie tracker using the TMDB API, since it's something I'd genuinely use myself. I updated `PROPOSAL.md` to cut the recommendation feature and add sort/filter of the logged list instead, and committed the change with a note explaining the peer feedback that drove it.

## What I learned

- Why a proposal needs an explicit "what I don't know yet" section: writing it forced me to actually name the parts I was unsure about (how to handle localStorage reliability, how to structure the API key) before I'd written any code, instead of discovering them mid-build.
- TMDB's API is free and doesn't require backend approval for personal use, which shaped the whole project scope, a static site with no server was realistic.
- Peer review is more useful early than late. Cutting the recommendation feature before writing any code for it saved time I would have spent building something out of scope.
