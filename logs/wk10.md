## What I learned

- **Static sites can't hide secrets.** I initially followed the standard advice of gitignoring my API key (`js/config.js`), which is correct for apps with a backend. But GitHub Pages only serves static files, so a file that's never pushed to GitHub can never be loaded by the live site either. My search feature was silently broken until I understood *why* that pattern doesn't apply to a no-backend deploy, not just that it was broken.
- **CSS `height` doesn't apply to inline elements.** My genre/decade bar charts were rendering with zero visible height because I'd used `<span>` (inline by default) for the bar track and fill. Adding `display: block` fixed it. Small fix, but a good reminder to actually diagnose *why* a rule isn't applying instead of guessing at random properties.
  ```css
  .bar-track { display: block; height: 10px; }
  .bar-fill { display: block; height: 100%; }
  ```
- Repo hygiene matters for grading, not just for tidiness: separate repo for the final project (not nested in `oim3690`), a `.gitignore` that actually matches where files live, and commit messages that describe *why* a change happened (e.g. "update proposal after peer feedback") rather than just "update file."
